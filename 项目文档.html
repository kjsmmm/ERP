1 项目概述

工厂模式
混合模式（OEM/ODM + 自有产品）

单工厂（预留多工厂扩展）
仓库数量

暂不考虑

核心原则

安全优先

  • 认证授权、数据加密、审计追踪
  • 企业级安全标准，不因开发便利妥协

稳固落地

  • 不追求技术时髦
  • 选择成熟稳定的技术栈

渐进交付

  • 纵向切片迭代
  • 每次迭代交付可用功能

预留扩展

  • 数据模型为多工厂留好接口
  • 架构支持未来多地点扩展

传输层

  • HTTPS 强制（TLS 1.2+）

存储层

  • 敏感字段加密存储（密码、身份证、银行卡）

接口防护

  • SQL 注入防护（参数化查询）
  • XSS 防护（输出编码）
  • CSRF 防护（Token 验证）

  • 接口级别限流，防暴力破解和 CC 攻击

5 工作流设计

集成策略：分阶段集成

第一阶段：轻度集成

  • Flowable 只负责审批流
  • 采购审批、订单变更审批等
  • 业务状态由代码管理
  • 目标：先把核心业务跑起来

第二阶段：深度集成（系统稳定后）

  • 将需要灵活配置的流程交给 Flowable
  • 生产工单流转、质检流程等
  • 平滑迁移，无需重写

审批场景

审批场景触发条件审批链
采购申请审批提交采购申请申请人 → 部门主管 → 厂长（金额>5000）
采购订单审批创建采购订单采购员 → 采购主管 → 财务确认
订单变更审批修改已确认订单销售员 → 销售主管 → 生产确认
不合格品处理质检不合格质检员 → 质量主管 → 技术判定
费用报销提交报销单申请人 → 部门主管 → 财务

7 迭代计划

策略：纵向切片

每次迭代交付一个完整可用的功能模块。第一个模块做完后形成的开发模式将成为后续模块的模板，效率逐迭代提升。

迭代时间线

迭代 0：基础设施搭建

1-2 周
  • 前端项目初始化（基于 Vben Admin）
  • 后端项目初始化（Spring Boot 3 脚手架）
  • 数据库初始化（MySQL + 建表脚本）
  • Docker 开发环境
  • 统一响应格式、全局异常处理
  • 日志框架、跨域配置、接口文档
  • 前后端联调验证
交付物：项目骨架、开发环境、框架跑通

迭代 1：用户认证 + 权限 + 客户管理

2-3 周
  • 登录/注销、用户管理、角色管理、部门管理
  • 客户 CRUD、客户分类、联系人管理
交付物：可登录、可管理客户的系统

迭代 2：产品管理 + BOM

2-3 周
  • 产品目录、产品分类、规格参数
  • BOM 物料清单、产品图片
交付物：可管理产品和物料清单

迭代 3：订单管理 + 库存基础

2-3 周
  • 销售订单 CRUD、订单状态流转
  • 库存查询、入库/出库、多仓库管理
交付物：可下单、可查看库存

迭代 4：生产管理

2-3 周
  • 生产工单、工艺路线、生产报工
  • 订单→生产计划→工单 的关联
交付物：可从订单生成工单、跟踪生产进度

迭代 5：采购管理 + 质量管理

2-3 周
  • 供应商管理、采购订单
  • 来料检验、过程检验、不合格品处理
交付物：采购和质检闭环

迭代 6：报表 + 工作流 + 收尾

2-3 周
  • 经营报表、生产报表、库存报表
  • Flowable 审批流集成
  • 系统优化、性能调优
交付物：完整可用的 ERP 系统
总工期
约 14-20 周（3.5-5 个月）
迭代数
7 个迭代（含基础设施）
